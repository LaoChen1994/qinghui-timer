# 0.3.2 交付验证报告

验证日期：2026-10-03。开发与桌面实测环境为 Apple Silicon Mac。

## 已交付功能

名称输入；45／60／90 分钟预设（默认 45 分钟）与 1～1440 整数分钟自定义周期；多怪物独立倒计时；击杀后单独重置；剩余 3 分钟和到点提醒弹框；系统通知权限入口；本地保存与重启恢复。

当前版本的精简窗口为 320×600 的竖条：隐藏品牌标题、统计和说明，只显示怪物名称、倒计时、细进度条、单条重置与四个时间微调按钮，保留置顶／展开按钮及窗内小提醒条。完整窗口尺寸／最大化状态仍可恢复。

新增 JSON 导入／导出，分享名称、周期、上次重置毫秒时间戳与刷新毫秒时间戳；导入不会从打开文件时重新起算。导入预览按名称匹配，不同名称新增，同名逐条选择覆盖或保留，本地同名多条时指定覆盖目标。整批校验、统一确认并原子保存；失败不改当前记录。已到期记录显示「已刷新」，不补发历史提醒，重复导入完全相同记录保留原提醒状态。

计时按照绝对刷新时间计算，界面每秒读取 Rust 后台状态。到点保留「已刷新」，下方持续显示超过刷新时间的时长，由用户手动重置下一轮；同名记录互不影响。提醒状态和待确认提醒一起保存，避免重启重复生成已处理的提醒。

## macOS 实际窗口验证

原有计时和提醒功能在 0.1.0 打包后的 Tauri 应用中验证以下历史流程：

1. 创建 40 分钟和 1 分钟两个计时器，检查真实倒计时推进和本地保存。
2. 检查短周期的「即将刷新」提醒弹框，确认后不持续重复弹出。
3. 最小化窗口，等待到点，再恢复窗口，检查「已经刷新」弹框与状态。
4. 退出应用，启动通用版，检查长周期继续按原刷新时刻倒计时，已确认的到点提醒不再次弹出。
5. 单独重置长周期，确认重新显示 40:00，另一条已刷新记录不受影响。
6. 通过删除确认弹框清理两条测试记录，交付窗口回到空列表。

以上均通过。系统通知权限显示已开启，后台发送调用未报告错误；未将观察到系统通知横幅列为实测通过项。

0.1.0 精简模式另做过以下实测，均通过（当时尺寸为 320×420，本轮调整为 320×600）：

1. 从完整界面切为精简空窗口，窗口确实缩小为 320×420；可展开添加记录。
2. 创建 40 分钟和 1 分钟两条记录后切入精简模式，显示名称、倒计时与重置按钮。

4. 预提醒显示为小提示条；保留提示条时重置另一只怪物成功，短周期倒计时继续。
5. 确认预提醒，实际等待到点，再次出现「已经刷新」提示条，卡片变为「已刷新」。
6. 确认到点提醒并展开，继续显示同一批记录。窗口放大后切换精简模式，再展开，恢复的截图尺寸与切换前一致。

3. 切为 320×600 竖条，截图为 Retina 640×1200；没有大标题／统计／说明，显示名称、倒计时、预计刷新和重置按钮。单独重置一条后核对其余三条时间戳保持不变。

6. 通过应用的删除确认清理本轮创建的四条测试记录，交付数据回到空列表。

## 0.3.1 Windows 精简窗口横向溢出修复

原先 `body` 固定最小宽度为 320px，Windows 传统纵向滚动条占用内部宽度后，页面不能收缩。提醒列表的默认 Grid 轨道还可能被长名称撑宽。移除页面的固定最小宽度，精简怪物列表和提醒列表均改用可收缩的 `minmax(0, 1fr)` 轨道；长名称沿用已有的省略显示。

修改前新增回归测试分别复现了 303px 可用宽度下页面横向溢出，以及 320px 下批量长名称提醒的内部横向溢出。修复后 31 项界面测试和生产构建通过。新增两项测试用 9 条长名称记录，分别在 320px 与 303px 视口检查无提醒、即将刷新、已经刷新及点击确认后的页面与提醒列表宽度；按钮均未超出可用宽度，列表能纵向滚动到最后一条。303px 用于模拟 320px 窗口被传统滚动条占用 17px，不代表 Windows 实机测试。已检查修复后的批量提醒截图。

Windows 0.3.1 中文安装包交叉编译与 NSIS 打包成功，交付文件与构建产物逐字节一致，SHA-256 已记录。此轮仅调整 CSS 布局与应用版本，没有修改 Rust 计时逻辑或用户数据；macOS 可用安装包仍为已验证的 0.3.0。

## 0.3.2 已刷新后的已过时间

按用户确认保留「已刷新」，下方增加小字「已过 MM:SS」；满一小时后使用 HH:MM:SS，小时超过 24 继续累计。用 Rust 快照的当前时间减去原刷新时间戳，向下取整到秒，不新增计时或保存字段；从原有每秒快照更新，也适用于重启、休眠恢复及导入的到期记录。重置或加时恢复倒计时后隐藏已过时间。

37 项界面测试和生产构建通过。新增用例检查刚过期不到一秒、59:59、01:00:00、25:01:01 及长时长，完整卡片不超过 94px、精简卡片不超过 82px；303px 可用宽度下无横向溢出且重置按钮未超出边界。固定后台时间增加一秒时显示由 01:00 变为 01:01，重载按原时间戳恢复；加时显示 01:00、重置显示 90:00，两者均隐藏已过时间。原批量提醒和纵向滚动测试继续通过。

最终 macOS 0.3.2 通用版实测通过：保留原有已到期记录的刷新时刻 11:47:21，完整窗口在 16:28:26 显示「已刷新／已过 04:41:05」，切入 320×600 精简窗口显示双行状态且时间继续推进。退出并重新启动后，16:35:52 显示「已过 04:48:31」，与原刷新时刻一致，没有从零重新计时。已检查真实精简窗口截图及更新后的 [卡片预览](cards-preview.png)，原有怪物记录与测试前逐项完全一致。此轮没有操作原记录的重置或微调按钮，这些流程由界面回归测试覆盖。
